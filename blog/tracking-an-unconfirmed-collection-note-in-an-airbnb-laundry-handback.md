## Why the collection note and the handback question should stay in one file

A short-stay host in Sarawak often ends up holding two pieces of paper about the same linen: the note written when laundry was collected, and a later question about what came back. Filing them apart is where confusion begins. The collection note records what left the property. The handback question records what someone wants clarified on return. They describe different moments, so neither should overwrite the other.

The practical answer is a single file with three parts: the original note kept exactly as written, a dated addendum that answers the handback question separately, and a named closure owner who confirms the file can be closed. Keeping the original intact matters because a rewritten note loses the evidence of what was actually recorded at collection. The addendum carries the later explanation without disturbing it.

This guide is written for Sarawak households, accommodation operators and venue managers who handle short-stay linen. It is a filing method, not a dispute procedure, and it does not tell you what your own agreement with a guest or a laundry provider says. Where a question touches contractual terms, the written terms and any quotation or service confirmation govern. That is a useful reminder that the paperwork around a collection is part of the record, not an afterthought.

## The worksheet: four fields that keep the record honest

Before writing anything new, set up a worksheet with four fields. First, the original note: transcribe it as it stands, including any abbreviations, without tidying the wording. Second, the open question: write the handback question in one sentence, in the words of the person who raised it, and mark it open. Third, the addendum: a dated entry that responds to the question and states what it relies on. Fourth, the closure owner: the name of the role or person responsible for deciding the question is answered and the file can be marked closed.

A fifth field is optional but helpful: a short list of what the addendum does not cover. If the handback question asks about something the collection note never recorded, say so plainly rather than filling the gap with assumption. A note that stays silent on an item is not proof the item was absent; it is simply silent.

Keep the worksheet plain. Avoid colour codes that only one person understands, and avoid overwriting a cell. If a correction is needed, add a new dated line beneath the old one. The aim is a file a colleague can read cold, months later, without asking you what a highlighted box meant. Treat the worksheet as a working document that grows by addition, not by replacement.

## Worked example: a generic bag label and a question about what came back

Picture an invented Sarawak host, whom we will call the host throughout this guide, filing a collection note for a short-stay flat. The note reads simply: one bag, label B-14, collected. Nothing else. Weeks later a handback question arrives asking whether the bag held a particular set of items.

The host does not rewrite the original note. Instead the file gains a dated addendum: the collection note for label B-14 recorded one bag and no item list; the handback question asks about contents; the addendum cannot confirm contents from the note alone. The closure owner is named as the person who will check any separate item list before the question is marked answered.

This example is deliberately dull, and that is the point. The bag label is generic, the note is short, and the addendum does not pretend to know more than the note did. What the file gains is a clear boundary between what was recorded and what is being asked. A reader can see the original, see the question, and see who owns the next step.

Hosts who use Airbnb laundry services regularly will recognise the pattern: collection notes are often brief because they are written at the door, while handback questions are written later and in more detail. The worksheet holds both without letting the later, longer document quietly become the only version of events.

## Writing the dated addendum without turning it into a verdict

An addendum answers a question; it does not settle blame. Write it in three short moves. State the question being answered. State what the original note and any other filed document actually say. State what remains unknown and who will resolve it.

Use dates as labels, not as arguments. A dated line tells a reader when the addendum was written; it does not by itself prove anything about what happened earlier. Keep the addendum in the same file as the original note so the two are always read together.

Resist the urge to add detail you cannot support. If the collection note did not list contents, the addendum should say the note did not list contents. If a separate list exists elsewhere, reference it by its own label rather than copying it in, so the file does not create a second, unofficial version.

For operators handling larger volumes, the same discipline scales. A venue manager filing several collection notes can use one addendum per open question, each pointing back to its own original note. ## Naming a closure owner and deciding when the file is closed

An open question with no owner tends to stay open. Name one closure owner per file, by role if not by person, and write that name on the worksheet. The owner does not have to answer the question personally; they have to confirm that someone has, in writing, and that the answer sits in the file.

A simple closure test helps. The file can be marked closed when the addendum responds to the question as written, any referenced document is identified, and the closure owner has recorded a dated line saying so. If any of those three is missing, the question stays open and the file stays open with it.

Treat this test as an author heuristic, not a standard. It is a way to keep a small file tidy, not a rule imposed by anyone else. Adjust it to suit how your own records are kept.

One more habit is worth adopting: when a file closes, leave the original note and the addendum in place. Do not delete the question because it has been answered. A closed file that still shows the question and the response is more useful than a clean file that shows neither. The same applies whether the file covers one flat or a whole building's linen.

## Where a laundry provider fits into the record

The worksheet is yours to keep, but the collection itself involves a provider, and that shapes what the note can contain. A collection note written at handover is usually short because it is written quickly. The provider's own paperwork, such as a quotation, invoice or written service confirmation, may carry more detail, and the addendum should point to that paperwork rather than duplicate it.

For hosts in Sarawak, knowing the provider's operating pattern helps with filing. Those details belong in the file only as context for when a note was written or a question raised, not as proof of anything about the items themselves.

Keep the division clear. The provider's terms and confirmations describe the service relationship. Your worksheet describes your own filing. Neither replaces the other, and a tidy worksheet does not settle a question that only the written terms can answer. If a handback question turns on what the terms say, the closure owner should read the terms and record which document was consulted, rather than relying on memory of the collection day.
